# Module 05: Phishing Analysis

> **Overview:** Phishing is the #1 initial access vector investigated by Tier 1 SOC analysts. This module covers dissecting raw `.eml` files, tracing SMTP headers, extracting indicators using specialized phishing analysis tools, and email authentication standards (`SPF`, `DKIM`, `DMARC`).

---

## Chapter 1: Phishing Analysis Fundamentals

### Crucial Email Header Fields for Investigation
When triaging a reported phishing email (`.eml` or `.msg`), always inspect the **Raw Headers / View Original**:

| Header Field | What It Reveals to a SOC Analyst |
| :--- | :--- |
| `From:` | The display name and sender address shown in the recipient's email client (easily spoofed!) |
| `Return-Path:` / `Envelope-From` | The actual bounce address used by SMTP servers (`MAIL FROM`); often exposes the real attacker domain |
| `Reply-To:` | Where replies are sent if the victim clicks "Reply" (frequently differs from `From:` in BEC attacks) |
| `Received:` | Trace of every mail server hop from sender to recipient (**read from bottom to top!**). The bottom-most `Received:` header contains the **originating sender IP** (`X-Originating-IP` / `X-Sender-IP`) |
| `Message-ID:` | Unique identifier generated by the sending mail server (`<id@domain>`) |
| `Authentication-Results:` | Shows whether `SPF`, `DKIM`, and `DMARC` checks passed or failed |
| `Content-Type:` | Defines MIME structure (`multipart/mixed` indicates attachments; `text/html` indicates HTML body) |
| `Content-Transfer-Encoding:` | Often `base64` or `quoted-printable` — used to decode obfuscated HTML bodies or extract attachments |

## Chapter 2: Phishing Emails in Action

### Common Evasion & Deception Techniques Used by Attackers
1. **Typosquatting / Lookalike Domains (IDN Homograph Attacks):**
   - Registering domains that visually mimic legitimate brands (`paypaI.com` using an uppercase `I`, `rnicrosoft.com` using `rn` instead of `m`, or Punycode Unicode characters `xn--...`).
2. **Open Redirects & URL Shorteners:**
   - Using legitimate domains with redirect parameters (`https://google.com/url?q=https://evil.com`) or URL shorteners (`bit.ly`, `tinyurl.com`) to bypass simple domain blocklists.
3. **HTML / Pixel Tracking & Image-Only Emails:**
   - Embedding the entire phishing message inside a single clickable image so text-based spam filters cannot scan keywords.
4. **Attachment Smuggling & Living off Trusted Sites (LOTS):**
   - Hosting credential harvesting forms on legitimate cloud platforms (`Google Forms`, `OneDrive`, `IPFS`, `Cloudflare Workers`, `Firebase`) so the domain has a clean reputation and valid TLS certificate.

## Chapter 3: Phishing Analysis Tools

### Essential Analyst Toolkit for Phishing Triage
1. **Header Analyzers:**
   - **Google Admin Toolbox Messageheader** (`toolbox.googleapps.com/apps/messageheader`) & **MXToolbox Header Analyzer**: Parse complex `Received:` chains into a visual hop-by-hop timeline and highlight SMTP delays or spoofed headers.
2. **Automated Email Dissection (`PhishTool` / `EMLAnalyzer`):**
   - **PhishTool:** Automatically parses `.eml` files into Hop Timelines, Headers, Extracted URLs, MIME parts, and Attachments, allowing one-click hash/URL lookups without opening the malicious email in an email client.
   - **CLI Inspection (`emlAnalyzer` / `base64`):**
     ```bash
     emlAnalyzer -i suspicious.eml --header --html -u --text --extract-all
     ```
3. **URL & Website Sandboxes (Safe Detonation):**
   - **UrlScan.io** & **Browserling / Any.Run:** Visit suspicious phishing links inside an isolated cloud browser, capturing a live **screenshot** of the fake login page, DOM HTML source, redirected domains, and TLS certificate details without exposing the corporate network.
4. **File & Attachment Reputation:**
   - Extract the attachment's **SHA-256 hash** (`sha256sum attachment.docm`) and search the hash on **VirusTotal**, **MalwareBazaar**, or **Hybrid Analysis** before ever detonating the file in a sandbox.

## Chapter 4: Phishing Prevention

### Email Authentication Protocols (`SPF`, `DKIM`, `DMARC`)
Because baseline **SMTP** has no built-in mechanism to verify if a sender is authorized to use a domain name, three DNS-based security standards work together to prevent email spoofing:

| Protocol | Full Name | How It Works | DNS Record Example |
| :--- | :--- | :--- | :--- |
| **SPF** | **Sender Policy Framework** | Publishes a DNS `TXT` record listing all authorized **IP addresses/subnets** allowed to send email on behalf of the domain (validates the `Return-Path` / `MAIL FROM` domain) | `v=spf1 ip4:192.0.2.0/24 include:_spf.google.com -all` (`-all` = HardFail, `~all` = SoftFail) |
| **DKIM** | **DomainKeys Identified Mail** | Digitally signs outgoing emails (headers + body hash) using the organization's **Private Key** (`DKIM-Signature` header). Receiving servers verify the signature using the **Public Key** published in DNS (`<selector>._domainkey.example.com`) | Ensures **Authenticity** and **Integrity** in transit |
| **DMARC** | **Domain-based Message Authentication, Reporting & Conformance** | Checks **Identifier Alignment** (does the visible `From:` header domain match the authenticated `SPF` and/or `DKIM` domain?) and tells receiving servers what policy to enforce on failures (`p=none`, `p=quarantine`, `p=reject`) | `v=DMARC1; p=reject; rua=mailto:dmarc@example.com` |

### Defense-in-Depth Against Phishing
- **Technical Controls:** Secure Email Gateways (SEG), stripping/blocking dangerous attachment extensions (`.exe`, `.scr`, `.hta`, `.lnk`, `.iso`, `.vbs`), disabling Office macros from the internet via Group Policy, and enforcing **Phishing-Resistant MFA (FIDO2 / WebAuthn Passkeys)**.
- **Human Controls:** Regular phishing simulations and clear one-click `"Report Phishing"` buttons in Outlook/Gmail.

## Chapter 5: Practical Labs (The Greenholt Phish & Snapped Phish-ing Line)

### End-to-End Phishing Investigation Checklist
1. **Extract Sender & Recipient Metadata:**
   - Compare `From:` vs. `Return-Path:` vs. `Reply-To:`.
   - Identify the originating IP from the earliest `Received:` header and check its reputation on **AbuseIPDB** / **Cisco Talos** / **VirusTotal**.
2. **Decode Obfuscated Body Content:**
   - If the email body is `Content-Transfer-Encoding: base64` or `quoted-printable`, decode it in **CyberChef** (`From Base64` or `From Quoted Printable`) to reveal hidden URLs.
3. **Inspect Hyperlinks & Attachments:**
   - Extract all URLs (`Extract URLs` in CyberChef), defang them (`Defang URL`), and check where they resolve.
   - Hash any attachments (`sha256sum`) and inspect them for credential-harvesting HTML forms (`attachment.shtml` / `.html`) or malicious macros.
4. **Scope the Impact in the SIEM / Email Logs:**
   - Search mail server logs for the same `Subject`, `Sender IP`, or attachment `SHA256` to see how many other employees received the email.
   - Search Web Proxy / DNS / EDR logs to determine if any recipient actually **clicked the link** (`HTTP POST` to the phishing domain) or **executed the attachment**!
